## Verified compliant

- Upstream provenance now fails closed on absent AS-auth provenance during PS validation: missing `GetGrantAsync(...).Provenance` returns invalid (`src/AAuth/Tokens/UpstreamTokenValidator.cs:178-L183`), and the test `PersonServerFullValidation_AsIssuedTokenWithoutProvenance_Rejected` covers the store-loss/no-record shape (`tests/AAuth.Conformance/AuthTokens/UpstreamTokenValidationTests.cs:193-L203`). This is correct for fresh chained requests, distinct from RA-CHAIN-001’s already-pending outbound send gap.
- Provenance records keep the original caller across chains (`src/AAuth/Person/AAuthPersonServerEndpoints.cs:668-L685`) and are retained past token expiry until retention cleanup (`src/AAuth/Server/InMemoryJtiStore.cs:169-L179`); tests cover pruning and quota (`TokenInventoryTests::Provenance_PrunesAtTokenExpiryPlusRetention`, `::Provenance_DistinctResourceQuotaRejectsBeforeAdditionalMint`, `::Provenance_QuotaBreachReturns429BeforeMinting`, `tests/AAuth.Conformance/Discovery/TokenInventoryTests.cs:166-L235`).
- Revoked original caller agent tokens and agent-person bindings cause `revoked_upstream_token` even if the upstream token itself is not revoked (`src/AAuth/Tokens/UpstreamTokenValidator.cs:192-L194`; `RevocationLifecycleTests::UpstreamFromRevokedCallingAgent_IsRevokedUpstreamToken`, `::UpstreamFromRevokedBinding_IsRevokedUpstreamToken`, `tests/AAuth.Conformance/Discovery/RevocationLifecycleTests.cs:138-L176`).
- Source dependency checks now run on PS polling, AS polling/callbacks, local mint, and the normal final federation send (`src/AAuth/Person/AAuthPersonServerEndpoints.cs:531-L540`, `src/AAuth/Person/AAuthPersonServerEndpoints.cs:2047-L2049`, `src/AAuth/Person/AAuthPersonServerEndpoints.cs:2271-L2277`, `src/AAuth/Access/AAuthAccessServerEndpoints.cs:457-L481`, `src/AAuth/Access/AAuthAccessServerEndpoints.cs:712-L717`).
- AS response delivery is pinned to access-role tokens via `expectedDwk: AuthTokenBuilder.AccessDwk` (`src/AAuth/Tokens/AuthTokenResponseValidator.cs:80-L86`).
- Payment federation composes `402 -> settlement -> poll -> 202 claims -> 200` and the payment seam receives only challenge/origin/pending URL (`src/AAuth/Access/AccessServerClient.cs:145-L260`, `src/AAuth/Access/AAuthPayment.cs:59-L96`).

## Not assessed

- Full browser/e2e call-chain samples and docs beyond the static helper/tests cited here.
- Non-slice revocation cascade endpoints, resource-managed authorization, mission revocation, R3 single-use gates, and AP token lifecycle outside their interaction with source dependencies.
