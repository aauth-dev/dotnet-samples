## Verified compliant

- The PS binding invariant is enforced with an atomic bind-or-verify store and generationed revocation inventory, not by directed `sub` reuse ([`AgentPersonBindingStore.cs`](../../../../src/AAuth/Person/AgentPersonBindingStore.cs):31; [`AgentPersonBinding.cs`](../../../../src/AAuth/Person/AgentPersonBinding.cs):21).
- Default person-token subjects are pairwise HMAC outputs scoped by PS, person key, and resource, and are persisted by enrollment records ([`PersonSubjectDeriver.cs`](../../../../src/AAuth/Person/PersonSubjectDeriver.cs):38; [`PersonResourceEnrollmentStore.cs`](../../../../src/AAuth/Person/PersonResourceEnrollmentStore.cs):29).
- First default issuance for a new resource does not mint immediately; it fetches resource metadata and parks a `202` consent entry before enrollment/minting ([`AAuthPersonServerEndpoints.cs`](../../../../src/AAuth/Person/AAuthPersonServerEndpoints.cs):785, :986, :992).
- Auth-token `updated_request` replacement state is active-state replacement, not append-only mutation: expiry, source dependencies, resource/presented token strings, scope, and interaction are all replaced together ([`AAuthPersonServerEndpoints.cs`](../../../../src/AAuth/Person/AAuthPersonServerEndpoints.cs):613, :632; [`IPersonPendingStore.cs`](../../../../src/AAuth/Person/IPersonPendingStore.cs):171).
- PS and agent token-request inputs share one validator for platform, printable Unicode device values, and capability-token grammar ([`AAuthProtocolInput.cs`](../../../../src/AAuth/Protocol/AAuthProtocolInput.cs):21, :36, :119; [`TokenExchangeRequest.cs`](../../../../src/AAuth/Agent/TokenExchangeRequest.cs):111, :122).
- Clarification deadlines and round limits are enforced on the agent and PS/federated paths ([`DeferredExchange.cs`](../../../../src/AAuth/Agent/DeferredExchange.cs):171; [`AAuthPersonServerEndpoints.cs`](../../../../src/AAuth/Person/AAuthPersonServerEndpoints.cs):646, :2190).
- Resource-response interactions now have PS-first relay with local fallback on unavailable relay ([`AAuthClientBuilder.cs`](../../../../src/AAuth/AAuthClientBuilder.cs):818; [`InteractionHandler.cs`](../../../../src/AAuth/Agent/InteractionHandler.cs):140).

## Not assessed

- Runtime behavior under build/test execution; the brief prohibited `dotnet build`/`dotnet test`, so all conclusions are static plus grep-test evidence.
- Durable store atomicity beyond the in-memory `IAgentPersonBindingStore`/`IPersonResourceEnrollmentStore` implementations.
- Samples/docs alignment except where tests referenced SDK behavior.
- Whether explicit-subject `IdentityAssertion.Assert(personKey, subject)` should be treated as host-preapproved first-resource consent. The default SDK path now gates first issuance; explicit subjects remain a host approval seam.
