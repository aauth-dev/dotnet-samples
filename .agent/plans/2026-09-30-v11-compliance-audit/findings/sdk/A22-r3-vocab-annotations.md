## Verified compliant

- Standard vocabulary URNs are exact for MCP, OpenAPI, gRPC, GraphQL, AsyncAPI, WSDL, and OData — `src/AAuth.R3/Model/Vocabulary.cs:6-L12`; spec (#r3-vocabulary-registry, L786-L792) and summary L868-L874.
- Unknown standard-namespace vocabularies are rejected unless a non-standard custom schema is configured — `src/AAuth.R3/Model/R3VocabularySchemas.cs:86-L92`; spec (#resource-metadata-extensions, L146) and IANA registry L786-L792.
- `r3_vocabularies` is emitted under the correct field name and request vocabularies must be advertised in metadata — `src/AAuth.R3/R3Metadata.cs:9`, `src/AAuth.R3/R3Metadata.cs:38-L39`; spec (#resource-metadata-extensions, L146), (#authorization-endpoint-extensions, L414).
- Vocabulary operation request shapes reject wrong identifier members, extra standard qualifiers, malformed gRPC method names, missing GraphQL `type`, invalid GraphQL `type`, invalid AsyncAPI `action`, OData bound-operation methods, duplicate operation members, and non-string `methods` — `src/AAuth.R3/Model/R3Operation.cs:80-L123`, `src/AAuth.R3/Model/R3VocabularySchemas.cs:51-L80`; spec (#mcp-vocabulary, L166), (#openapi-vocabulary, L184), (#grpc-vocabulary, L202), (#graphql-vocabulary, L222-L224), (#asyncapi-vocabulary, L239-L240), (#wsdl-vocabulary, L260-L261), (#odata-vocabulary, L278-L279).
- `r3_operations` client bodies use the correct field names and validate non-empty operations — `src/AAuth.R3/R3Request.cs:11-L17`, `src/AAuth.R3/R3Request.cs:20-L27`, `src/AAuth.R3/Model/R3Grant.cs:27-L38`; spec (#authorization-endpoint-extensions, L412-L416).
- Auth/resource token R3 claim names are exact (`r3_uri`, `r3_s256`, `r3_granted`, `r3_per_call`) and granted/per-call vocabularies must match — `src/AAuth.R3/R3AuthClaims.cs:9-L12`, `src/AAuth.R3/R3AuthClaims.cs:29-L34`, `src/AAuth.R3/R3ClaimReader.cs:37-L48`; spec IANA claims L763-L767.
- OpenAPI/AsyncAPI and MCP annotation encodings use the specified keys, reject writer-side `session-token`, enforce budget+agent/person writer rejection, and compute the spec floor of `auth-token` for malformed budget combinations read from a peer — `src/AAuth.R3/R3AccessAnnotations.cs:20-L24`, `src/AAuth.R3/R3AccessAnnotations.cs:34-L42`, `src/AAuth.R3/R3AccessAnnotations.cs:46-L63`, `src/AAuth.R3/R3AccessAnnotations.cs:67-L76`; spec (#access-mode-annotation, L312), (#budget-annotation, L324), (#applying-annotations, L328-L334), (#vocabulary-encodings, L342-L358).
- No JSON annotation encoding is exposed for gRPC, GraphQL, or WSDL — `src/AAuth.R3/R3AccessAnnotations.cs:83-L92`; spec (#no-annotation-encoding, L377-L385).
- The R3 AS token endpoint mints `r3_granted` and optional `r3_per_call` from the fetched R3 document/proposal rather than from access annotations — `src/AAuth.R3/R3AccessTokenEndpoint.cs:67`, `src/AAuth.R3/R3AccessTokenEndpoint.cs:423-L450`; spec (#applying-annotations, L334).
