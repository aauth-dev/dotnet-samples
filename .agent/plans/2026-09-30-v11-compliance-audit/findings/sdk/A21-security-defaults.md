## Verified compliant

- PoP consumer path verifies a single `Signature`, `Signature-Input`, and `Signature-Key`, resolves the presented key, and verifies the HTTP Message Signature before accepting token claims — `src/AAuth/Server/Verification/AAuthVerificationMiddleware.cs:93`, `src/AAuth/Server/Verification/AAuthVerificationMiddleware.cs:114`, `src/AAuth/Server/Verification/AAuthVerificationMiddleware.cs:124` (`#proof-of-possession`, L2833).
- Production server identifiers are exact `https://` origins with lowercase DNS names only; IP literals and `localhost` are rejected unless an explicit development loopback policy is supplied — `src/AAuth/Discovery/AAuthEgressPolicy.cs:73`, `src/AAuth/Discovery/AAuthEgressPolicy.cs:80` (`#tls-requirements`, L2935).
- Outbound URL admission rejects non-HTTPS except explicit loopback development origins, rejects endpoint query strings where endpoints are expected, and validates literal IP addresses — `src/AAuth/Discovery/AAuthEgressPolicy.cs:95`, `src/AAuth/Discovery/AAuthEgressPolicy.cs:102`.
- SSRF defenses cover private, loopback, documentation, link-local, and multicast/reserved destinations; `169.254.169.254` is explicitly denied — `src/AAuth/Discovery/AAuthEgressPolicy.cs:161`, `src/AAuth/Discovery/AAuthEgressPolicy.cs:174`.
- DNS rebinding is defended by resolving the full address set, validating every address, and connecting to pinned numeric endpoints through `ConnectCallback` — `src/AAuth/Discovery/AAuthEgressPolicy.cs:137`, `src/AAuth/Discovery/AAuthEgressPolicy.cs:141`, `src/AAuth/Discovery/AAuthHttpTransport.cs:79`.
- Redirects, proxies, oversized headers, oversized bodies, and slow responses are bounded by default — `src/AAuth/Discovery/AAuthHttpTransport.cs:72`, `src/AAuth/Discovery/AAuthHttpTransport.cs:73`, `src/AAuth/Discovery/AAuthHttpTransport.cs:76`, `src/AAuth/Discovery/AAuthHttpTransport.cs:77`, `src/AAuth/Discovery/AAuthHttpTransport.cs:152`, `src/AAuth/Discovery/AAuthHttpTransport.cs:157`, `src/AAuth/Discovery/AAuthHttpTransport.cs:169`.
