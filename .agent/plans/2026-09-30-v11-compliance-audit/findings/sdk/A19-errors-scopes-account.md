## Verified compliant

- Error-response helper emits `Content-Type: application/problem+json`, a required `error` member, optional `detail`, and no `error_description` — `src/AAuth/Server/AAuthProblemDetails.cs:7`, `src/AAuth/Server/AAuthProblemDetails.cs:95`, `src/AAuth/Server/AAuthProblemDetails.cs:98`, `src/AAuth/Server/AAuthProblemDetails.cs:100`.
- Signature failures produced through `AAuthProblemDetails.SignatureErrorResult` are bodyless `401` responses carrying only `Signature-Error`; `Accept-Signature-Alg` / `Accept-Signature-Scheme` are only added by verification failure handling for unsupported algorithm/scheme, not by 403 problem responses — `src/AAuth/Server/AAuthProblemDetails.cs:72`, `src/AAuth/Server/AAuthProblemDetails.cs:76`, `src/AAuth/Server/AAuthProblemDetails.cs:77`, `src/AAuth/Server/Verification/AAuthVerificationMiddleware.cs:398`, `src/AAuth/Server/Verification/AAuthVerificationMiddleware.cs:406`, `src/AAuth/Server/Verification/AAuthVerificationMiddleware.cs:408`.
- Token endpoint client parsing fails closed for unknown error codes: any parseable non-success `error` becomes `AAuthTokenExchangeException`, and every code except `server_error` is terminal — `src/AAuth/Agent/TokenExchangeClient.cs:320`, `src/AAuth/Agent/TokenExchangeClient.cs:323`, `src/AAuth/Errors/AAuthTokenExchangeException.cs:64`; the conformance test covers all 17 published token codes — `tests/AAuth.Tests/Agent/ChallengeHandlerTests.cs:567`.
- `PollingErrorCode` models all registered polling codes and maps them case-sensitively (`StringComparer.Ordinal`-equivalent switch) — `src/AAuth/Errors/PollingError.cs:11`, `src/AAuth/Errors/PollingError.cs:14`, `src/AAuth/Errors/PollingError.cs:17`, `src/AAuth/Errors/PollingError.cs:23`, `src/AAuth/Errors/PollingError.cs:26`, `src/AAuth/Errors/PollingError.cs:29`, `src/AAuth/Errors/PollingError.cs:32`, `src/AAuth/Errors/PollingError.cs:76`; tests cover terminal typed detail outcomes — `tests/AAuth.Conformance/Errors/PollingErrorTests.cs:134`.
- Resource-token production rejects scopes not declared by the resource's `scope_descriptions` or the PS `scopes_supported`, with exact case-sensitive lookup — `src/AAuth/Tokens/ResourceTokenBuilder.cs:89`, `src/AAuth/Tokens/ResourceTokenBuilder.cs:172`, `src/AAuth/Tokens/ResourceTokenBuilder.cs:177`, `src/AAuth/Tokens/ResourceTokenBuilder.cs:181`.
- Auth-token scope narrowing is enforced on consumption with exact, case-sensitive membership; route authorization also uses exact set membership and does not do prefix matching — `src/AAuth/Tokens/TokenVerifier.cs:245`, `src/AAuth/Tokens/TokenVerifier.cs:246`, `src/AAuth/Tokens/TokenVerifier.cs:248`, `src/AAuth/Server/Verification/AAuthVerificationMiddleware.cs:438`, `src/AAuth/Server/Authorization/AAuthScopeHandler.cs:36`.

- Mission endpoint `mission_terminated` uses status 403 and the problem format with `mission_status` extension — `src/AAuth/Server/Governance/GovernanceEndpoints.cs:178`, `src/AAuth/Server/Governance/GovernanceEndpoints.cs:180`, `src/AAuth/Server/Governance/GovernanceEndpoints.cs:182`.

## Not assessed / out of slice

- Revocation endpoint wire behavior beyond the `RevocationError` type names — governed by the token-revocation slice, not A19.
- Full deferred-flow retry, retention, and pending URL semantics — covered by A14; A19 only records polling error code/status modelling and wire vocabulary overlap.
- Resource-managed two-party interaction endpoint (`AAuthInteractionEndpointExtensions`) has additional non-table codes (`unknown_pending`, 401 `invalid_request`) but was not in the assigned code list; I read it only to avoid confusing it with PS/AS polling.
- Scope duplicate rejection: the assigned draft-11 scope lines require declared values and non-broadening but do not explicitly state a duplicate-token rule; code collapses duplicates with `HashSet` / `Split(...RemoveEmptyEntries)`, so I did not grade it as a spec violation without a normative line.
