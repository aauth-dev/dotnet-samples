## Verified compliant

- Unknown selected schemes reject as `unsupported_scheme`, while unselected unsupported members are ignored by selecting only the verified label — `SignatureKeyParser.cs:84`–`:85`, `SignatureKeyHeader.cs:36`–`:41`; covered by `SignatureV10AdversarialTests.cs:399`–`:409`.
- Label presence is enforced on the consumer side for the selected label — `AAuthVerifier.cs:69`–`:74`, `StructuredFields.cs:33`–`:38`.
- Every SDK-produced signature covers `signature-key` after populating that header value — `AAuthSigningHandler.cs:228`–`:229`, `:264`–`:268`, `:291`–`:293`.
- `hwk` rejects `kid`, `jwk`, `jkt`, and private/symmetric material; public JWKs require supported, fully specified `alg` consistent with `kty`/`crv` — `SignatureKeyParser.cs:38`–`:45`, `KeyFactory.cs:36`–`:53`.
- `jwks_uri` requires `id`, `dwk`, `kid`, rejects obsolete `uri`, checks metadata `issuer` byte-equals `id`, and validates the selected JWKS key before use — `SignatureKeyParser.cs:46`–`:55`, `DefaultSignatureKeyResolver.cs:133`–`:145`, `JwksClient.cs:102`–`:106`.
- `jwks` applies egress admission, resolves by `kid`, validates only the selected key, and does not require unselected JWKS members to be usable — `DefaultSignatureKeyResolver.cs:147`–`:154`, `JwksClient.cs:97`–`:106`, `:119`–`:130`.
- `jkt-jwt` supports `jkt-s256+jwt`, requires header `jwk`, validates durable-key thumbprint against `iss`, verifies the JWT signature with the header key, validates time, and extracts/validates `cnf.jwk` — `NamingTokenVerifier.cs:18`–`:29`, `:55`–`:65`.
- `jkt-jwt` producer emits the required `typ`, `alg`, header `jwk`, `iss`, `iat`, `exp`, `jti`, and `cnf.jwk` — `NamingJwtBuilder.cs:33`–`:52`.
- `jwt`/`jkt-jwt` cache requests require a `jti`, `self-jwt` rejects both `cache` and any `cnf` claim — `SignatureKeyParser.cs:67`–`:82`.
- `self-jwt` reuses the discovered issuer key as the HTTP signing key and forbids `cnf` — `SignatureKeyParser.cs:77`–`:78`, `DefaultSignatureKeyResolver.cs:99`–`:101`.
- AAuth-specific defaults enforce agents using `jwt`: default verification accepts only `jwt`, and AAuth agent/person/auth token types smuggled under non-`jwt` schemes are rejected — `AAuthVerificationOptions.cs:14`, `AAuthVerificationMiddleware.cs:186`–`:200`; server-own signing uses `jwks_uri` via `AAuthSigningKeySetHandler.cs:13`–`:15`.

## Not assessed / out of slice

- Full RFC 9421 signature-base canonicalization, body coverage, and replay/JTI store behavior except where needed for Signature-Key label and coverage checks.
- Revocation, cached-carrier issuance, `Signature-Key-Cache`, and `Accept-Signature-Alg` advertisement beyond scheme/key validation paths.
- Trust policy for AAuth token issuers, mission/resource-token flows, and downstream authorization semantics.
- X.509/cached carrier internals, because they are documented unsupported in this SDK snapshot.
