## Verified compliant

- `AAuth-Requirement` producers use the required `requirement=<token>` member for agent/person/auth token challenges — `src/AAuth/Headers/AAuthRequirementHeader.cs:35`-`66`.
- Unknown requirement parameters are tolerated by the shared parser and ignored by typed projections that read only known parameters — `src/AAuth/Headers/AAuthRequirementHeader.cs:94`-`116`, `src/AAuth/Headers/Interaction.cs:76`-`91`.
- `requirement=interaction` producer emits a `202` body, `AAuth-Requirement`, `Location`, `Cache-Control: no-store`, and caller adds `Retry-After` — `src/AAuth/Server/Verification/AAuthHttpContextExtensions.cs:205`-`218`, `src/AAuth/Server/ResourceManaged/AAuthResourceManagedHttpContextExtensions.cs:47`-`50`.
- Interaction code generation uses Crockford base32 with at least 8 symbols from a CSPRNG; the browser-facing default uses 26 symbols — `src/AAuth/Headers/InteractionCode.cs:48`-`66`, `src/AAuth/Server/BrowserConsentSessions.cs:15`-`20`.
- Code comparison normalizes hyphens, case, and Crockford aliases before comparing — `src/AAuth/Headers/InteractionCode.cs:75`-`131`, `src/AAuth/Server/BrowserConsentSessions.cs:223`-`233`.
- Browser consent sessions consume a valid arrived code and rate-limit failed code attempts, terminating the pending interaction after repeated failures — `src/AAuth/Server/BrowserConsentSessions.cs:236`-`241`, `src/AAuth/Server/BrowserConsentSessions.cs:297`-`322`.
- `requirement=approval` is recognized on `202`; the agent notifies/polls without user URL handling — `src/AAuth/Agent/InteractionHandler.cs:140`-`145`, `src/AAuth/Agent/InteractionHandler.cs:151`-`161`.
- `AAuth-Access` token68 grammar rejects empty, whitespace, controls, and multiple credentials at the pure parser level — `src/AAuth/Headers/AAuthAccessHeader.cs:35`-`80`, `tests/AAuth.Conformance/ResourceTokens/AAuthAccessTokenGrammarTests.cs:21`-`48`.
- `Authorization: AAuth` is covered by signatures when present and required by the verifier — `src/AAuth/HttpSig/AAuthSigningHandler.cs:269`-`273`, `src/AAuth/HttpSig/AAuthSigningHandler.cs:331`-`335`, `src/AAuth/HttpSig/AAuthVerifier.cs:131`-`134`.
- Resource-managed opaque tokens are bound to the polling/requesting agent key thumbprint and expire in the resource-side store — `src/AAuth/Server/ResourceManaged/AAuthInteractionEndpointExtensions.cs:84`-`91`, `src/AAuth/Server/Verification/AAuthHttpContextExtensions.cs:148`-`151`, `src/AAuth/Server/IOpaqueTokenStore.cs:60`-`70`.
- AAuth token exchange requests send capabilities in JSON request bodies rather than `AAuth-Capabilities` headers on the SDK-owned PS exchange channel — `src/AAuth/AAuthClientBuilder.cs:596`-`602`, `src/AAuth/Agent/TokenExchangeClient.cs:247`-`260`.
