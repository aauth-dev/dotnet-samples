## Verified compliant

- Exact AAuth `typ` strings are present for agent/person/auth/resource tokens — `src/AAuth/AAuthConstants.cs:105`, `src/AAuth/AAuthConstants.cs:108`, `src/AAuth/AAuthConstants.cs:111`, `src/AAuth/AAuthConstants.cs:114`; enum parsing maps them exactly at `src/AAuth/AAuthTokenType.cs:40`-`src/AAuth/AAuthTokenType.cs:45`.
- Agent-token producer emits `typ: aa-agent+jwt`, `dwk: aauth-agent.json`, `iss`, `sub`, `jti`, `iat`, `exp`, and `cnf.jwk` — `src/AAuth/Tokens/AgentTokenBuilder.cs:164`-`src/AAuth/Tokens/AgentTokenBuilder.cs:180`.
- Additional agent-token claims cannot overwrite built-in claims — `src/AAuth/Tokens/AgentTokenBuilder.cs:193`-`src/AAuth/Tokens/AgentTokenBuilder.cs:201`.
- Required common/header claims and agent-token `sub`/`ps`/`parent_agent` types are checked before verification — `src/AAuth/Tokens/TokenVerifier.cs:631`-`src/AAuth/Tokens/TokenVerifier.cs:668`, with `cnf.jwk` required at `src/AAuth/Tokens/TokenVerifier.cs:705`-`src/AAuth/Tokens/TokenVerifier.cs:706`.
- Wrong `typ` / wrong `dwk` are rejected in direct and JWKS verification — `src/AAuth/Tokens/TokenVerifier.cs:109`-`src/AAuth/Tokens/TokenVerifier.cs:120`, `src/AAuth/Tokens/TokenVerifier.cs:470`-`src/AAuth/Tokens/TokenVerifier.cs:480`.
- `alg` is allowlisted to fully specified asymmetric algorithms on JWKS paths; `none`, `EdDSA`, and symmetric alg names are rejected — `src/AAuth/Tokens/TokenVerifier.cs:464`-`src/AAuth/Tokens/TokenVerifier.cs:468`.
- JWKS lookup uses `iss` + expected `dwk` metadata and JWT header `kid`, not an embedded token key — `src/AAuth/Tokens/TokenVerifier.cs:492`-`src/AAuth/Tokens/TokenVerifier.cs:512`; `Signature-Key` JWT resolution does the same at `src/AAuth/HttpSig/DefaultSignatureKeyResolver.cs:84`-`src/AAuth/HttpSig/DefaultSignatureKeyResolver.cs:85`.
- `exp` is checked against the verifier clock with no skew and future `iat` is rejected past the configured 60-second default — `src/AAuth/Tokens/TokenVerifier.cs:144`-`src/AAuth/Tokens/TokenVerifier.cs:160`.
- `cnf.jwk` is parsed as public key material and must carry a supported fully specified JWK `alg` — `src/AAuth/HttpSig/SignatureKeyParser.cs:97`-`src/AAuth/HttpSig/SignatureKeyParser.cs:107`, `src/AAuth/Crypto/KeyFactory.cs:35`-`src/AAuth/Crypto/KeyFactory.cs:48`.
- For `Signature-Key: jwt` agent tokens, the resolver returns the verified token's `cnf.jwk` as the HTTP verification key, and the HTTP verifier uses that key for the request signature — `src/AAuth/HttpSig/DefaultSignatureKeyResolver.cs:99`-`src/AAuth/HttpSig/DefaultSignatureKeyResolver.cs:101`, `src/AAuth/HttpSig/AAuthVerifier.cs:110`-`src/AAuth/HttpSig/AAuthVerifier.cs:111`.
- Duplicate JSON members in JWT header/payload/cnf are rejected recursively — `src/AAuth/HttpSig/SignatureKeyParser.cs:114`-`src/AAuth/HttpSig/SignatureKeyParser.cs:129`.
- Token body parameters reject wrong token-type slots before endpoint-specific logic — `src/AAuth/Server/TokenRequestBody.cs:30`-`src/AAuth/Server/TokenRequestBody.cs:45`.
- A top-level `agent_token` with `parent_agent` is rejected for direct authorization, and `subagent_token` must name the requesting parent and share issuer — `src/AAuth/Tokens/AgentIssuanceContext.cs:65`-`src/AAuth/Tokens/AgentIssuanceContext.cs:67`, `src/AAuth/Tokens/AgentIssuanceContext.cs:90`-`src/AAuth/Tokens/AgentIssuanceContext.cs:94`.
