## Not assessed / out of slice

- Server-side PS/AS validation of token-exchange bodies, resource-initiated interaction redirects, callback handling, code single-use/rate-limits, consent rendering, and clarification sanitization are server obligations owned by other slices.
- Direct `TokenExchangeClient.ExchangeAsync(personServer, ...)` trusts its caller-supplied PS; I did not classify that as a resource-redirection defect because the automatic challenge path verifies the resource token against the selected PS before exchange.
- Platform registry membership could not be fully assessed from this slice because the vendored registry section establishes the registry but does not define a finite in-document value set to validate against.
