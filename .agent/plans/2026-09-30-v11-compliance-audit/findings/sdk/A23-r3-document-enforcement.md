## Verified compliant

- Resource-token and auth-token extension claim names are `r3_uri`, `r3_s256`, `r3_granted`, and `r3_per_call` — `src/AAuth.R3/R3AuthClaims.cs:9`; resource tokens write URI/hash at `src/AAuth.R3/R3Challenge.cs:103`; auth tokens write grants at `src/AAuth.R3/R3AuthClaims.cs:37`.
- AS processing fetches the R3 document/proposal before minting and verifies the exact fetched bytes against `r3_s256` — `src/AAuth.R3/R3AccessTokenEndpoint.cs:411`; `src/AAuth.R3/R3AccessTokenEndpoint.cs:455`; `src/AAuth.R3/R3FetchClient.cs:48`; `src/AAuth.R3/R3Hash.cs:9`.
- SSRF/cross-origin swaps are constrained: AS fetch rejects an `r3_uri` whose origin differs from the verified resource issuer — `src/AAuth.R3/R3FetchClient.cs:61`; `src/AAuth.R3/R3AccessTokenEndpoint.cs:463`.
- Auth-token `r3_granted`/`r3_per_call` shape is parsed as `{ vocabulary, operations }`, requires `r3_granted`, and requires matching vocabularies when both claims are present — `src/AAuth.R3/R3ClaimReader.cs:37`; `src/AAuth.R3/R3ClaimReader.cs:47`.
- Resource enforcement rejects operations absent from both grants and per-call lists, and challenges only operations present in `r3_per_call` — `src/AAuth.R3/R3Enforcement.cs:50`; `src/AAuth.R3/R3Enforcement.cs:55`; `src/AAuth.R3/R3Enforcement.cs:66`.
- Per-call retries bind the auth token hash to the stored proposal hash and verify actual parameters: inline JSON uses structural equality and digest parameters hash presented bytes — `src/AAuth.R3/R3Enforcement.cs:111`; `src/AAuth.R3/R3Enforcement.cs:145`; tests cover tampering at `tests/AAuth.R3.Tests/ResourceR3Tests.cs:313`.
- Unsigned or agent-signed document fetches are rejected by the mapped endpoint trust path — `src/AAuth.R3/R3DocumentEndpoint.cs:79`; `src/AAuth.R3/R3DocumentEndpoint.cs:90`; `src/AAuth.R3/R3DocumentReaderPolicy.cs:20`; tests at `tests/AAuth.R3.Tests/ResourceR3Tests.cs:137`.
- The proposal store keys retained bytes by the content hash and returns copies, preserving exact bytes for hash verification — `src/AAuth.R3/R3ProposalStore.cs:35`; `src/AAuth.R3/R3ProposalStore.cs:49`.

## Not assessed / out of slice

- Core JWT `typ`/`aud`/`iss`/expiry validation is delegated to `TokenVerifier` and the AAuth Protocol slice, not this R3 slice.
- TLS termination / deployment-level HTTPS enforcement was not assessed beyond producer/fetch URI validation; `SPEC-VERSION.md` treats platform/native transports as deployment responsibilities.
- Sample-specific retained-result handling in `tests/AAuth.R3.Tests/BookingsPolicyTests.cs:40` was read only as contrast; samples are outside this SDK slice and do not fix `R3Enforcement`'s reusable API.
- Budget accounting for release-gated or failed calls is out of scope because Budgets are a documented unsupported area in `aauth-spec/SPEC-VERSION.md`.
