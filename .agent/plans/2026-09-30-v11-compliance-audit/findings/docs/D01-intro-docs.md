## Verified compliant

- The glossary uses the draft-11 token type names `aa-agent+jwt`, `aa-person+jwt`, `aa-resource+jwt`, and `aa-auth+jwt` — `docs/glossary.md:31-35`, matching common token `typ` requirements (`#aauth-tokens`, L2299) and token-specific sections.
- The glossary uses draft-11 `presented_token`, `presented_jti`, `upstream_token`, `mission_s256`, and `dwk` terminology — `docs/glossary.md:35`, `:43`, `:50`, `:127`, matching `#ps-token-endpoint` L940-L943 and `#resource-token` L743-L746.
- The resource-side example uses the high-level `app.UseAAuth(...)` with an explicit auth-token issuer allow-list, not bare `UseAAuthVerification()` — `docs/getting-started.md:326-335`; no SDK-01 unsafe low-level recommendation was found in this slice.
- No claims of implemented Budgets, `accept_signature_algs`, X.509/cached Signature-Key carriers, or `aauth-resource` link-relation support were found in the scoped files. `docs/README.md:158-159` says metadata/JWKS fetchers cache responses, not that the unsupported cached carrier is implemented.
- Spot-checked relative links in the four scoped files resolved on disk.
