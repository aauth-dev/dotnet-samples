## Verified compliant

- `docs/signing-modes/agent-token-jwt.md:3-17` correctly says AAuth agents use `sig=jwt` and agent tokens are `aa-agent+jwt`; protocol `#agent-tokens` L508-L544 and `#keying-material` L2179 require this.
- `docs/signing-modes/agent-token-jwt.md:99-107` correctly describes issuer JWKS verification plus request-signature verification against `cnf.jwk`; Signature-Key `jwt` verification is L1102-L1219.
- `docs/signing-modes/pseudonymous-hwk.md:3-8` correctly scopes `hwk` to generic Signature Keys and says AAuth agents present agent/auth tokens using `jwt`; protocol L2179 and L2196 agree.
- `docs/signing-modes/overview.md:138-160` correctly states body-bearing PS/AS/revocation requests cover `content-type` and `content-digest`, and SDK options enforce it (`AAuthVerificationOptions.RequireBodyCoverage`, `src/AAuth/Server/Verification/AAuthVerificationOptions.cs:18-25`).
- `docs/advanced/platform-attestation.md:3-10`, `:80-101` correctly states the SDK exposes only the hook and does not ship WebAuthn/App Attest verification or a standardized `attestation_challenge`; `SPEC-VERSION.md` L30-L38 lists platform/native transports and production policy as deployment responsibilities.
- `docs/advanced/key-management.md:190-219` matches `AAuthSigningKeySet` live issuer-key rotation (`src/AAuth/Crypto/AAuthSigningKeySet.cs:18-72`) and does not claim unsupported X.509/cached key carriers.
