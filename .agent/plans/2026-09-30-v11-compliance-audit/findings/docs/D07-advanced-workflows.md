## Verified compliant

- Call-chaining prose correctly says the `upstream_token` is a body parameter, not the signing credential, and that downstream routing uses the upstream token's `iss`/`ps`, not the intermediary agent token's `ps` — protocol `#call-chaining` L1846-L1857; `docs/workflows/call-chaining.md:132-140`, `:371-379`.
- Clarification Chat documents `requirement=clarification`, response-body `clarification`, the three actions (`clarification_response`, `updated_request`, `DELETE`), required `presented_token`, and unchanged replacement-token claims consistently with `#clarification-chat` L1048-L1126 — `docs/advanced/clarification-chat.md:24-63`, `:163-175`.
- Document Release correctly places resource-initiated interaction before PS consent and abandonment on callback error — protocol `#resource-initiated-interaction` L986-L994; `docs/workflows/document-release.md:30-43`.
- Events docs correctly describe subscribe tokens as `Signature-Key: sig=jwt`, event tokens as `self-jwt`, required durable record before `202`, `remaining_uses` on bounded accepted delivery, and no body for unlimited delivery — Events L194-L235, L399-L435; `docs/workflows/events.md:12-19`, `:67-80`, `:112-119`.
- Catalog docs correctly state operation identity is vocabulary plus `operationId` and that colliding backend operation IDs must be renamed in a merged OpenAPI definition — R3 `#operation-identifier-scope`; `docs/workflows/catalog-gateway.md:3-9`, `:28-32`.
- Wallet AS-issued grant chaining correctly routes via the PS named by the auth token's `ps`, carries `upstream_token` in the request body, and does not present the upstream grant as Concierge's carrier — protocol `#call-chaining` L1846-L1857; `docs/workflows/wallet-protocol.md:62-73`, `:83-91`.
